# ChocAn Data Processing System (Chocoholics Anonymous)
A professional **local-host** ChocAn Data Processing System web application that implements the ChocAn workflow and reporting requirements (provider terminal, manager/operator tools, weekly accounting procedure, and Acme simulation).

This repo contains:\n- `backend/`: **FastAPI + SQLite + SQLAlchemy** (secure cookie-based login, role-based access)\n- `frontend/`: **React (Vite) + TypeScript + React Router** (professional dashboard UI)\n- `generated_reports/`: plain `.txt` report files generated by the weekly accounting procedure\n- `chocan/`: the **original Flask/JSON prototype** kept for reference (not used by the rebuilt app)

## Stack
- **Frontend**: React + Vite + TypeScript, React Router\n- **Backend**: FastAPI, SQLite, SQLAlchemy ORM, Pydantic\n- **Auth**: password hashing + **HTTP-only cookie session**\n- **Reports**: generated `.txt` files saved into `generated_reports/`

## Setup & run (Windows / PowerShell)
Open **two terminals** from the repo root.

### Backend (FastAPI)
```powershell
python -m venv backend\.venv
backend\.venv\Scripts\python -m pip install -r backend\requirements.txt

# Reset + seed database (creates backend/chocan.sqlite3)
backend\.venv\Scripts\python -m backend.app.seed --reset

# Run backend
backend\.venv\Scripts\uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
```

Backend health check: `http://127.0.0.1:8000/api/health`

### Frontend (Vite)
```powershell
cd frontend
npm install
npm run dev
```

Open: `http://127.0.0.1:5173/`

## Reset/seed the database anytime
```powershell
backend\.venv\Scripts\python -m backend.app.seed --reset
```

## How this matches the professor’s ChocAn requirements
- **Login page first**: app lands on login, session stored securely via HTTP-only cookie.\n- **Roles**: Provider, Manager/Operator, Admin.\n- **Member validation**: provider enters 9-digit member number → Validated / Invalid number / Member suspended.\n- **Provider verification**: provider user is linked to a valid 9-digit provider number; billing uses that provider automatically.\n- **Service billing**: requires DOS (MM-DD-YYYY), member #, service code (6 digits), optional comments (<=100). Service code is looked up from Provider Directory.\n- **Provider Directory**: services listed alphabetically with code + fee.\n- **Member/Provider records**: full address fields + status.\n- **Weekly accounting procedure**: manager button generates member reports, provider reports, manager summary, and EFT file.\n- **Report files saved**: written into `generated_reports/` and downloadable from the manager UI.\n- **Acme simulation**: manager tool to suspend/reinstate members.
